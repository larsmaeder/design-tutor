# Knowledge areas and levels

Levels describe how well the student can **read code** in an area. They say nothing about design skill.

## Areas

| Area | Covers |
|---|---|
| Structure & semantics | HTML elements, document structure, semantic meaning |
| Styling & tokens | CSS selectors, the cascade, colour, typography, custom properties / design tokens |
| Layout & responsive | box model, flexbox, grid, media and container queries |
| Motion & states | interaction states, transitions, animation |
| Behaviour & data | JavaScript: events, the DOM, state, fetching data, loading/empty/error states |
| Components & frameworks | React and similar: components, props, state, composition, routing |
| Accessibility | semantics, ARIA, keyboard and focus, contrast, screen readers |
| Tooling & delivery | git, terminal, package managers, dev servers, build tools, deployment |

## Levels (applied per area)

| Level | Starting point in this area | How to teach |
|---|---|---|
| **Beginner** | Hasn't read code in this area yet. | Explain every term on first use, with an everyday comparison. Very small steps. Always say which file and where. Show 3–5 lines. Check questions ask about the visible result ("what changed on screen?"). |
| **Intermediate** | Recognises the structure and common building blocks. | Cover basics in a few words and go deeper on new concepts. Longer snippets are fine. Check questions ask *why* something happened. |
| **Advanced** | Reads it comfortably. | Focus on trade-offs, scalability, accessibility and maintainability. Explain less. Check questions ask the student to choose between approaches. |

If an area isn't listed in `TUTOR.md`, treat it as **Beginner**.
